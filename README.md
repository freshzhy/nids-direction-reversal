# Feature–label direction reversal in cross-network intrusion detection

Code, configuration, per-run results and paper sources for

> H. Zhang, M. Wang. *When features change sides: feature–label direction reversal underlies predictive inversion in cross-network intrusion detection.* Manuscript submitted to *Computer Networks*.

Every number, table and figure in the manuscript is generated by `scripts/r7_paper_assets.py` from the result files in `results/`; no number in `paper/main.tex` is typed by hand.

## Repository layout

```
config.yaml              main protocol: NetFlow v2, DoS/DDoS-aligned task (run "dos_v1")
configs/binary.yaml      NetFlow v2, heterogeneous binary task (run "binary_v1")
configs/dos_v3.yaml      NetFlow v3, DoS/DDoS-aligned task (run "dos_v3")
run_reversal.sh          full pipeline (resumable; finished jobs are skipped)
src/                     preprocessing, models, reversal analyses, paper statistics
scripts/
  01_preprocess.py       identifier removal, log1p, de-duplication, per-class sampling pools
  r1_transfer.py         single-source and leave-one-network-out transfer, class swap
  r2_feature_reversal.py univariate AUC and robust directions per network and seed
  r3_audit.py            duplicate audit of the raw NetFlow v2 files
  r4_report.py           working report and figures (results/reversal_summary/)
  r5_alignment.py        oracle intervention (marginal alignment, flip, random-flip control) and threshold sensitivity
  r6_few_label.py        few-label direction estimation and target-only baselines
  r7_paper_assets.py     paper/generated/: numbers.tex, LaTeX tables, figures
tests/                   unit and end-to-end tests on synthetic data
results/<run>/reversal/  per-run result files used by the paper (CSV)
results/<run>/env.json   library versions used for the run
results/audit.csv        duplicate audit (Section 4.1 and Table 1)
data/processed/<run>/    preprocessing summaries (stats.csv, features.csv, attack_types.csv, meta.json)
paper/                   LaTeX sources (elsarticle) and generated assets
```

Run names map to the paper as follows: `dos_v1` = NFv2, DoS/DDoS-aligned; `binary_v1` = NFv2, heterogeneous binary; `dos_v3` = NFv3, DoS/DDoS-aligned.

## Installation

Python 3.12 or 3.13.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q tests        # runs in about a minute on synthetic data
```

## Reproducing the paper from the included results (no raw data needed)

```bash
python scripts/r7_paper_assets.py          # regenerates paper/generated/
cd paper && latexmk -pdf main.tex          # requires a TeX distribution with elsarticle, lmodern, adjustbox
```

## Reproducing the experiments from the raw data

The NetFlow datasets are not redistributed here. Download the NetFlow v2 and v3 versions of UNSW-NB15, CSE-CIC-IDS2018, ToN-IoT and BoT-IoT from the University of Queensland NIDS datasets page (https://staff.itee.uq.edu.au/marius/NIDS_datasets/) and place them in the repository root under these directory names (the data CSV is found anywhere inside each directory):

```
NF-UNSW-NB15-v2/   NF-CSE-CIC-IDS2018-v2/   NF-ToN-IoT-v2/   NF-BoT-IoT-v2/
NF-UNSW-NB15-v3/   NF-CICIDS2018-v3/        NF-ToN-IoT-v3/   NF-BoT-IoT-v3/
```

Then run

```bash
bash run_reversal.sh                # all cores
N_JOBS=8 bash run_reversal.sh       # limit parallel workers
```

The NetFlow v3 run is skipped automatically if the four `NF-*-v3` directories are absent. The script preprocesses each protocol (writing sampling pools to `data/processed/<run>/*.parquet`), runs r1–r6, the audit, the working report and r7, and compiles the paper if `latexmk` is available. The reported runs used an Apple M1 Ultra workstation; see `results/<run>/env.json` for library versions.

Seeds 0–4 determine both the per-seed balanced samples and model initialisation, so results are reproducible up to numerical differences between library versions and platforms.

## What is not included

- Raw NetFlow datasets and the derived sampling pools (`*.parquet`): obtain them from the dataset providers as described above.
- Intermediate caches and logs.
